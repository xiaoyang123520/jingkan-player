# 净看 0.2.5：全屏与播放性能合并版

本版整合上一轮 0.2.5-fullscreen.1 的独立全屏按钮和本轮播放性能修复。源码和构建产物均已准备供统一发布；本目录本身不代表已经推送或创建 GitHub Release。

## 为什么 Windows 首播比网页慢

网页播放链路可以直接把分块解密的视频交给支持 HEVC 的浏览器。Windows 客户端默认开启兼容播放，为不支持 HEVC 的环境转成 H.264。旧实现需要“完整下载 + 完整转换”两段串行等待，这不是仅仅界面加载慢。

本版对已验证能顺序输入的片源，将下载与转码重叠进行，保留最多 3 路有界下载和有序输入，不改变画质、H.264 编码参数与缓存预算。完整转换后播放，保留拖动进度和缓存复用；并非流式首帧播放。

## 合并改动

- 独立全屏/退出按钮与 Esc，可信本地页面以外仍不放行全屏权限。
- 下载与转码流水线，带长度校验、分块重试、背压、超时、退出终止及临时文件清理。
- 已就绪媒体不再额外等待可选画质列表；列表没有及时返回时保留当前画质。
- 保留上轮详情失败重试、过期响应隔离、模态焦点管理和异常临时文件清理。
- 新增流水线单元回归、真实 FFmpeg 的 H.264/AAC 输出及拖动解码验证，以及可复现离线基准。

离线基准是 Linux 系统 FFmpeg 与模拟网络，不是用户 Windows 电脑或真实 CDN 的提速承诺。Windows 原生运行、人工听音和跨版本安装更新仍需真实环境验收。

# 净看 0.2.5

Windows 10/11 x64 非官方短剧播放器，采用 [hongguoTV](https://github.com/sgsjsvc/hongguoTV) 内容引擎，与红果平台没有隶属关系。请仅观看有权观看的内容；不承诺全集、高清、所有地区或永久可播。

## 安装与升级

推荐使用 `Jingkan-Setup-0.2.5-x64.exe` 安装版，支持后续在线更新。安装不要求管理员权限，可自行选择目录。0.2.3 以及更早的 ZIP 版没有在线更新模块，必须先退出旧版并手动安装一次新版。

仍提供 `Jingkan-0.2.5-windows-x64.zip` 便携版：完整解压到新文件夹后打开 `Jingkan.exe`，不要在压缩包内运行或仅复制 EXE。ZIP 版不能原地自动安装更新，需要手动换包或迁移到安装版。

收藏、历史和播放进度继续使用 `%APPDATA%\JingkanPublicPlayer`；升级和默认卸载不主动删除它。不要同时运行两个版本。无需自行安装 Node.js、WebView2 或安卓模拟器。

实验版尚无商业代码签名，Windows 可能提示未知发布者。请核对下载来源和 SHA256，不要关闭安全软件或设置全局排除。

## 在线更新怎样工作

在“说明 → 版本与在线更新”查看状态。安装版启动时检查正式版本；发现新版后由你点击下载，显示下载进度；下载校验完成后，点击“重启并安装”，还需确认一次重启，才会关闭播放服务并执行安装。不自动下载、不在退出时偷偷安装，不接受预览版或降级。

更新基于 [electron-updater 的 NSIS 支持](https://www.electron.build/docs/features/auto-update/)，从项目自己的公开 GitHub Releases 获取 `latest.yml` 和安装程序，下载使用更新元数据中的 SHA512 完整性校验。完整性校验不能代替发布者代码签名；GitHub 账户与仓库仍需妥善保护。

**发布候选构建不等于已上线。** 未绑定真实仓库的构建会明确提示“尚未配置发布源”，不会访问虚构地址。正式发布前必须执行仓库配置脚本、重新构建并上传安装包和更新元数据；流程见 [发布说明](RELEASING.md)。GitHub 不可达或检查失败不会阻止正常播放。

更新请求会让 GitHub 及其下载服务看到 IP 等正常网络请求信息；不会发送收藏、历史或观看进度。没有遥测、广告 SDK、账号登录或云同步。

## 本轮加固

- 新增独立的受限更新接口、检查状态、按需下载及确认安装流程，继续使用沙箱、上下文隔离和主框架 IPC 来源校验。
- 运行依赖 axios 固定升级到 1.20.0，sm-crypto 固定升级到 0.5.7；新增 electron-updater 6.8.11。当前运行依赖审计没有已知漏洞，不代表软件绝对安全。
- 保留 0.2.3 的损坏本地记录容错、换源进度隔离、重复请求错误脱敏、退出等待清理，以及之前的瞬断重试和损坏缓存重建。
- 修复兼容播放缓存竞态：正在读取的缓存获得可释放租约，清理和刷新会避开活动读取，避免并发准备或缓存超限清理时影响播放。
- 准备可复现的 Windows 构建流程，并将历史调试素材、播放截图、个人配置、缓存和秘密文件排除在公开仓库之外。

## 播放慢或失败时

建议保持“兼容播放”勾选。对内容引擎已经验证为头部含 MP4 元数据的片源，兼容模式使用最多 3 路分块下载，按顺序直接送入本地 FFmpeg：下载和 H.264 转码重叠，不再先写完整输入文件后才开始转码。仍然需要完整转换后开始播放，不是边转边播，也不保证秒开。不能顺序输入的片源保留原先的缓存再转码路径。流水线下载与转换总上限为 10 分钟。只有本机支持 HEVC 解码时才尝试关闭兼容播放。

检查 `resources\ffmpeg\ffmpeg.exe` 是否完整、系统盘是否有空间，以及 `%APPDATA%\JingkanPublicPlayer\video-cache` 是否可写。网络、地区和上游接口变化仍可能导致播放失败，可稍后重试或降低画质。

缓存成品预算约 512 MB，单集原始输入上限 150 MB，转换仍需要输出文件临时空间。流水线路径不另存整集输入文件；其他片源仍需要额外输入临时空间。完全退出程序后可删除 `video-cache`，不影响收藏和历史。视频转换只在本机进行。

## 测试结果应如何理解

本地 Node 单元测试覆盖输入、并发、缓存、播放状态和模拟更新生命周期。离线 Linux Electron 回归使用自制无音轨样片，验证沙箱桥接、真实 FFmpeg 转换、解码、进度及界面状态。

这些检查**不等于 Windows 真机安装/跨版本更新验收、人工听音、长期连播或全部在线片源可用**。正式发布前仍需 Windows 上完成“安装 → 检查 → 下载 → 重启安装 → 数据保留”的实际跨版本测试；不能把模拟测试标成已经在线更新成功。

## 从源码构建

需要 Node.js 22.13+。推荐在 Windows 构建安装包：

```sh
npm ci
node scripts/prepare-ffmpeg.cjs
node scripts/configure-release.cjs 你的GitHub用户名/jingkan-player
npm run build:win
node qa/verify-package.cjs
```

单元测试在 Linux 运行 `npm test`；部分 FFmpeg 子进程测试使用 POSIX 测试脚本，不能宣称整套测试在 Windows 已通过。Windows 构建工作流先在 Linux 执行测试，再在 Windows 生成候选产物，**不会自动创建仓库或发布 Release**。

FFmpeg Windows 二进制不直接提交到 Git，准备脚本从固定上游附件下载并校验固定 SHA256。完整源码交付包包含该工具和许可。Electron 和 FFmpeg 来源见 [第三方声明](THIRD_PARTY_NOTICES.md)。
